各項目に、必須・推奨・変更可を明記しています。

1GitHubの新しい保管場所を作る

GitHubの「New repository」画面で、次のとおり入力します。

Owner 推奨自分のGitHubアカウントを選択
Repository name 変更可ein-bridge-publisher
Description 変更可Ein Bridge Publisher deployment source
Visibility 必須Public
Add a README file 推奨チェックしない
Add .gitignore 推奨None
Choose a license 推奨None

なぜPublicなの？
今回使う「Deploy to Cloudflare」方式では、配布元リポジトリがPublicであることが必要です。 コードだけを置き、管理パスワード、Googleの秘密情報、公開する資料HTMLは置きません。
ここではしないこと
ZIPファイルを1個だけアップロードしない。
パスワードやSESSION_SECRETをGitHubへ書かない。

2プロジェクトの中身をGitHubへ入れる

  1. GitHubで、今作った ein-bridge-publisher を開きます。
  2. uploading an existing file または Add file → Upload files を押します。
  3. ダウンロードしたZIPを「すべて展開」します。
  4. 展開したフォルダを開き、中にあるファイルとフォルダを全部アップロード欄へドラッグします。
  5. Commit messageは下の値を使います。
Commit message 変更可Initial Ein Bridge Publisher setup
Commit先 推奨Commit directly to the main branch

アップロード後に確認するもの
GitHubの最初の画面に、少なくとも次が直接見えていること。
  • package.json
  • wrangler.jsonc
  • src フォルダ
これらが、さらに同名の外側フォルダの中へ入っている状態は不可です。

3作ったGitHubのURLを確認する

URLは次の形になります。

https://github.com/あなたのGitHub名/ein-bridge-publisher

このURLをChatGPTへ貼ってください。ここから先のCloudflare画面を、表示内容に合わせて1画面ずつ案内します。

この段階では、Google Cloudの設定やSecret作成を先にしなくて大丈夫です。

別の方法に変えてもよい？

技術的には変えられます。ただし、今は次の標準ルートに固定します。

GitHubへコードを置く → Deploy to Cloudflare → Googleログイン設定 → 独自ドメイン接続

GitHub Desktop、npm、BAT、R2、Cloudflare Accessなどを使う別ルートもありますが、今回は使いません。途中で別方式へ変えると、手順と検証条件が変わるためです。
